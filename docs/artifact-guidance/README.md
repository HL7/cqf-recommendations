# CPG artifact guidance inventory

The original artifact-guidance pass verified 174 fragments in its Publisher output. This inventory and its hash checker describe that frozen candidate. Use the [current validation notes](../narrative-refresh/validation.md) and [current verifier](../narrative-refresh/verify.py) to review the branch after the STU 3 ballot integration and Publisher corrections. See the [artifact-guidance validation](validation.md) for the historical results.

This inventory establishes the narrative coverage baseline for 82 CPG Profile resources (7 artifact, 32 domain, 43 activity) and 5 CPG OperationDefinitions. It preserves the exact case-sensitive FSH `Id` or `Instance` for each target and records the last-build page that exists for it. The 28 extension profiles and 17 CHF example profiles remain outside this scope.

Each of the 87 in-scope artifacts needs two nonempty fragments in `input/intro-notes`: an `*-intro.md` overview and an `*-notes.md` implementation note. The expected total is 174 fragments. Existing one-line notes are eligible for replacement as part of the authorized narrative work. New narrative must explain the resource’s purpose and how it fits the CPG workflow without changing formal resources, templates, or configuration.

At inventory time, 75 expected intro files existed, 12 were missing, and no expected notes files existed. The directory also contained 17 CHF example intros, 1 extension intro, 5 obsolete orphan intros with no current matching declaration, and one unsuffixed legacy CHF file; the inventory names and preserves hashes for all 24 files, read from the frozen candidate rather than the mutable checkout. Those existing files remain untouched. The verifier permits those baseline files but flags new unexpected fragments.

`inventory.json` captures SHA-256 baselines for FSH, input JSON/XML/CQL, build configuration, and 288 template-source files, plus preservation hashes for all 57 narrative pagecontent files, 22 narrative SVGs, and the 24 out-of-scope intro-note files. It excludes 24 Publisher-generated, cache, or version files from the template baseline (`onLoad`/`onGenerate`/`onCheck`/JIRA outputs, `cache.ini`, and `versions.txt`; the frozen `ant.xml` generates `versions.txt` from the current IG). The manifest has 896 formal-source hashes: 608 repository sources/configuration and 288 template files. One checked template file, `packagelist.txt`, is generated by `ant-hl7.xml` from the fixed `packagelisturl` property; that output is deterministic for the current property, but the verifier will flag a change if the configured URL changes. `--candidate-root` can point to a fresh Publisher candidate; the verifier compares these template paths directly and omits the 24 listed runtime/cache outputs. Review any new template path that Publisher mutates before extending this baseline. Later ballot and Publisher changes are covered by the current branch verification.

The authorized narrative exception to the earlier 780-file guard covers exactly the 174 `intro_file` and `notes_file` paths listed by the 87 resources in `inventory.json`. Other pre-existing files under `input/intro-notes`, including the 24 preserved out-of-scope files, are not covered by that exception. The earlier guard manifest is not rewritten here.

`verify.py` also checks the historical `docs/narrative-refresh/protected-files.json` manifest without modifying it. Of its 780 entries, 75 paths intersect the exact 174 authorized fragment paths and are skipped; the remaining 705 files must retain their historical hashes.

Run the verifier from the repository root with the frozen candidate directory used for the template baseline:

```sh
python3 docs/artifact-guidance/verify.py --candidate-root /path/to/frozen-candidate
```

The verifier also renders all fragments in one Ruby Kramdown GFM pass and checks each notes usage anchor against its case-sensitive FSH `Id` or `Instance` plus `-usage`. Each notes file starts with an empty `<div id="..."></div>` anchor; the verifier confirms it renders as a `div`, adds no extra source heading, and creates no empty paragraph. Its smart-quote and typographic-symbol options match the Publisher's `template/config/_config.yml` (`apos`, `apos`, `quot`, `quot`; `<<` and `>>`) so injection comparisons preserve the rendered source punctuation. An optional `--site /path/to/generated/site/en` checks the English build's target pages and fragment links. Add `--require-injected` for a final build to prove both intro and notes text appears in the corresponding rendered page, that the notes usage anchor is attached to a `div`, and that the template's `Notes:` heading is not followed by a redundant “Using this” heading:

```sh
python3 docs/artifact-guidance/verify.py --candidate-root /path/to/frozen-candidate --site /path/to/generated/site/en --require-injected
```

The verifier checks narrative coverage, unique usage IDs, source and protected-artifact hashes, unexpected fragment files, normative language, notes usage anchors, and (when supplied) rendered page/link targets. A nonzero exit indicates an inventory or coverage mismatch that needs review; uppercase normative wording is reported for editorial review.
