This index lists the concepts of the [conceptual knowledge architecture](documentation-approach-12-conceptual-knowledge-architecture.html) in alphabetical order. Each concept links to where it is defined in the Approach section, and the table shows how the concept is represented by the profiles in this implementation guide.

The Approach pages use conceptual names (for example, "Recommendation") to describe the architecture separately from any particular representation. The profiles that represent these concepts in FHIR use "CPG"-prefixed names (for example, CPGRecommendationDefinition).

| Concept | Description | Represented by |
|---|---|---|
| <a id="concept-activity"></a>**[Activity](activityflow.html#purpose-and-rationale)** | An action or process taken as part of delivering guideline-directed care, such as ordering a medication or collecting information, tracked from definition to event | Definition, request, and event profiles for each activity type (see [Activity Flow](activityflow.html)) |
| <a id="concept-care-plan"></a>**[Care Plan](documentation-approach-12-05-cpg-careplan.html)** | The Plan applied to an individual patient: proposals, requests, and events scoped to a specific CPG | [CPGCarePlan](StructureDefinition-cpg-careplan.html) |
| <a id="concept-case"></a>**[Case](documentation-approach-12-02-separating-and-defining-case-plan-and-workflow.html#case)** | The information that describes a patient's current and historical state of health, disease, and risks | Case data: [Case Summary](documentation-approach-12-04-cpg-case.html#case-summary) (see below). A patient's enrollment in a pathway: [CPGCase](StructureDefinition-cpg-case.html) (EpisodeOfCare) |
| <a id="concept-case-feature"></a>**[Case Feature](documentation-approach-12-04-cpg-case.html#case-features)** | A fact about the patient, either recorded directly or derived or inferred from other case features | [CPGCaseFeatureDefinition](StructureDefinition-cpg-casefeaturedefinition.html) |
| <a id="concept-case-feature-group"></a>**[Case Feature Group](documentation-approach-12-04-cpg-case.html#case-feature-groups)** | A grouping of related case features | No dedicated profile |
| <a id="concept-case-feature-relationship"></a>**[Case Feature Relationship](documentation-approach-12-04-cpg-case.html#case-feature-relationships)** | A relationship between case features, optionally qualified by pertinence | No dedicated profile |
| <a id="concept-case-plan-progressing-note"></a>**[Case Plan Progressing Note](documentation-approach-12-07-cpg-derivative-and-related-assets.html#case-plan-progressing-note)** | A case plan summary combined with clinical impressions, describing the patient's progress along the pathway | [CPGCasePlanProgressingNote](StructureDefinition-cpg-caseplanprogressingnote.html) |
| <a id="concept-case-plan-summary"></a>**[Case Plan Summary](documentation-approach-12-07-cpg-derivative-and-related-assets.html#case-plan-summary)** | The case features relevant to a pathway, strategy, or recommendation, together with the related proposals, requests, and events | [CPGCasePlanSummaryDefinition](StructureDefinition-cpg-caseplansummarydefinition.html); instance: [CPGCasePlanSummary](StructureDefinition-cpg-caseplansummary.html) |
| <a id="concept-case-summary"></a>**[Case Summary](documentation-approach-12-04-cpg-case.html#case-summary)** | The set of case features and feature groups that represent the case data scoped by a CPG | [CPGCaseSummaryDefinition](StructureDefinition-cpg-casesummarydefinition.html); instance: [CPGCaseSummary](StructureDefinition-cpg-casesummary.html) |
| <a id="concept-ecase-report"></a>**[eCase Report](documentation-approach-12-07-cpg-derivative-and-related-assets.html#ecase-report)** | The data elements needed for outcomes research on the guideline topic and for feedback to improve the guideline | Not profiled here; see the [Electronic Case Reporting IG](http://hl7.org/fhir/us/ecr) |
| <a id="concept-event"></a>**[Event](documentation-approach-12-05-cpg-careplan.html#event-as-part-of-the-care-plan)** | A record of an activity that was performed, including the fulfillment of a request | Event resources (see [Profiles](profiles.html)) |
| <a id="concept-evidence"></a>**[Evidence](documentation-approach-12-03-cpg-plan.html#quality-of-evidence-and-evidence-for-recommendations)** | The body of evidence that informs a recommendation, and its quality | Evidence resources (see [EBM-on-FHIR](http://hl7.org/fhir/clinicalreasoning-evidence-and-statistics.html)) |
| <a id="concept-guideline"></a>**[Guideline](documentation-approach-12-07-cpg-derivative-and-related-assets.html#guideline)** | The container for all of the knowledge assets produced by CPG development | [CPGComputableGuideline](StructureDefinition-cpg-computableguideline.html) (ImplementationGuide) |
| <a id="concept-measure"></a>**[Measure](documentation-approach-12-07-cpg-derivative-and-related-assets.html#measure-ecqms)** | A population-level measurement, typically an aggregate of patient-level metrics | Not profiled here; see the [Quality Measure IG](http://hl7.org/fhir/us/cqfmeasures) |
| <a id="concept-metric"></a>**[Metric](documentation-approach-12-07-cpg-derivative-and-related-assets.html#metrics)** | A patient-level measurement or indicator, such as recommendation compliance, strategy adherence, or goal attainment | [CPGComputableMetric](StructureDefinition-cpg-computablemetric.html) (Measure); results: [CPGMetricReport](StructureDefinition-cpg-metricreport.html) (MeasureReport) |
| <a id="concept-pathway"></a>**[Pathway](documentation-approach-12-03-cpg-plan.html#pathways)** | The coordination of strategies and recommendations across the whole guideline | [CPGPathwayDefinition](StructureDefinition-cpg-pathwaydefinition.html) (PlanDefinition) |
| <a id="concept-pathway-eligibility-criteria"></a>**[Pathway Eligibility Criteria](documentation-approach-12-03-cpg-plan.html#pathway-eligibility)** | The logic that determines whether a patient is eligible for a pathway | Expressions on [CPGPathwayDefinition](StructureDefinition-cpg-pathwaydefinition.html); reusable cohorts may use [CPGGroupDefinition](StructureDefinition-cpg-groupdefinition.html) |
| <a id="concept-pathway-enrollment-criteria"></a>**[Pathway Enrollment Criteria](documentation-approach-12-03-cpg-plan.html#pathway-enrollment-criteria-as-a-profiled-eca-rule)** | The logic, expressed as an ECA rule, for enrolling an eligible patient in a pathway | Enrollment proposals: [CPGEnrollmentActivity](StructureDefinition-cpg-enrollmentactivity.html) |
| <a id="concept-pathway-enrollment-status"></a>**[Pathway Enrollment Status](documentation-approach-12-03-cpg-plan.html#pathway-enrollment)** | The current and historical status of a patient's enrollment in a pathway | Status of [CPGCase](StructureDefinition-cpg-case.html) (EpisodeOfCare) |
| <a id="concept-plan"></a>**[Plan](documentation-approach-12-02-separating-and-defining-case-plan-and-workflow.html#plan)** | How a class of patients should be managed, made up of recommendations, strategies, and a pathway. Distinct from the Plan phase of the [Activity Flow](activityflow.html#purpose-and-rationale) (a request with an intent of `plan`) | [CPGPathwayDefinition](StructureDefinition-cpg-pathwaydefinition.html), [CPGStrategyDefinition](StructureDefinition-cpg-strategydefinition.html), and [CPGRecommendationDefinition](StructureDefinition-cpg-recommendationdefinition.html) |
| <a id="concept-proposal"></a>**[Proposal](documentation-approach-12-05-cpg-careplan.html#proposal)** | A patient-specific recommendation | Request resources with intent `proposal`, such as [CPGServiceRequest](StructureDefinition-cpg-servicerequest.html), [CPGMedicationRequest](StructureDefinition-cpg-medicationrequest.html), and [CPGCommunicationRequest](StructureDefinition-cpg-communicationrequest.html) |
| <a id="concept-recommendation"></a>**[Recommendation](documentation-approach-12-03-cpg-plan.html#recommendations)** | A guideline recommendation, with its applicability criteria and recommended activity, expressed as an ECA rule | [CPGRecommendationDefinition](StructureDefinition-cpg-recommendationdefinition.html) (PlanDefinition) |
| <a id="concept-request"></a>**[Request](documentation-approach-12-05-cpg-careplan.html#request-as-part-of-the-care-plan)** | A plan, order, prescription, or other request that corresponds to or relates to a proposal. Proposals, plans, and orders all use the FHIR request pattern | Request resources (see [Profiles](profiles.html)) |
| <a id="concept-strategy"></a>**[Strategy](documentation-approach-12-03-cpg-plan.html#strategies)** | The coordination of a set of related recommendations, often for a particular clinical issue | [CPGStrategyDefinition](StructureDefinition-cpg-strategydefinition.html) (PlanDefinition); patient-specific: [CPGStrategy](StructureDefinition-cpg-strategy.html) (RequestGroup) |
| <a id="concept-workflow"></a>**[Workflow](documentation-approach-12-02-separating-and-defining-case-plan-and-workflow.html#workflow)** | How care is delivered in a particular setting. This guide does not specify local workflow | No dedicated profile. See the [Common Processes code system](CodeSystem-cpg-common-process-cs.html) and the FHIR request, event, and task patterns |
{: .grid}
