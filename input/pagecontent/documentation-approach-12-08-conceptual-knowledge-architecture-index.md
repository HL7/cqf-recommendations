Use this index to find the definition of a [conceptual architecture](documentation-approach-12-conceptual-knowledge-architecture.html) term and the profiles or resource patterns that express it.

The Approach uses names such as Recommendation and Case Feature for concepts. The index includes earlier CPG-prefixed names for lookup. When a legacy name also matches a profile, the last column distinguishes its scope.

| Concept | Description | Defined in | Represented by |
|---|---|---|---|
| <a id="concept-activity"></a>**Activity** | A unit of work that guidance can describe, propose or track | [Activity Flow](activityflow.html#purpose-and-rationale) | [CPGComputableActivityDefinition](StructureDefinition-cpg-computableactivity.html) for a reusable definition. The applicable Request, Task and Event resources convey patient-specific work. |
| <a id="concept-care-plan"></a>**Care Plan**<br/>Formerly: CPGCarePlan | Patient-specific planning that relates concerns, goals, proposed activities, authorized requests and documented outcomes. | [Care Plan](documentation-approach-12-05-cpg-careplan.html) | [CPGCarePlan](StructureDefinition-cpg-careplan.html) (CarePlan) |
| <a id="concept-case"></a>**Case**<br/>Formerly: CPGCase | Patient information relevant to the guideline, including recorded and inferred features. | [Case](documentation-approach-12-04-cpg-case.html) | Clinical resources carry patient information. [CPGCase](StructureDefinition-cpg-case.html) (EpisodeOfCare) records enrollment. |
| <a id="concept-case-feature"></a>**Case Feature**<br/>Formerly: CPGCaseFeature, CPGFeature | A clinically meaningful observation, assessment, request or inference about a patient. | [Case Features](documentation-approach-12-04-cpg-case.html#case-features) | Definition: [CPGCaseFeatureDefinition](StructureDefinition-cpg-casefeaturedefinition.html) (StructureDefinition). Patient values can come from clinical resources or be computed as inferences. |
| <a id="concept-case-feature-group"></a>**Case Feature Group**<br/>Formerly: CPGCaseFeatureGroup | A grouping of related case features | [Case Feature Groups](documentation-approach-12-04-cpg-case.html#case-feature-groups) | No dedicated profile |
| <a id="concept-case-feature-relationship"></a>**Case Feature Relationship**<br/>Formerly: CPGCaseFeatureRelationship | A relationship between case features, optionally qualified by pertinence | [Case Feature Relationships](documentation-approach-12-04-cpg-case.html#case-feature-relationships) | No dedicated profile |
| <a id="concept-case-plan-progressing-note"></a>**Case Plan Progressing Note**<br/>Formerly: CPGCasePlanProgressingNote | A case-plan summary with clinical impressions that describe the patient’s progress. | [Case Plan Progressing Note](documentation-approach-12-07-cpg-derivative-and-related-assets.html#case-plan-progressing-note) | [CPGCasePlanProgressingNote](StructureDefinition-cpg-caseplanprogressingnote.html) |
| <a id="concept-case-plan-summary"></a>**Case Plan Summary**<br/>Formerly: CPGCasePlanSummaryView | The case features relevant to a pathway, strategy, or recommendation, together with the related proposals, requests, and events | [Case Plan Summary](documentation-approach-12-07-cpg-derivative-and-related-assets.html#case-plan-summary) | [CPGCasePlanSummaryDefinition](StructureDefinition-cpg-caseplansummarydefinition.html); instance: [CPGCasePlanSummary](StructureDefinition-cpg-caseplansummary.html) |
| <a id="concept-case-summary"></a>**Case Summary**<br/>Formerly: CPGCaseSummary, CPGCaseSummaryView | A selected view of case features scoped to a guideline and point in time. | [Case Summary](documentation-approach-12-04-cpg-case.html#case-summary) and [derivative assets](documentation-approach-12-07-cpg-derivative-and-related-assets.html#case-summary) | [CPGCaseSummaryDefinition](StructureDefinition-cpg-casesummarydefinition.html) (GraphDefinition) and [CPGCaseSummary](StructureDefinition-cpg-casesummary.html) (Composition) |
| <a id="concept-ecase-report"></a>**eCase Report**<br/>Formerly: CPGeCaseReport | Patient information scoped to an applicable electronic case reporting contract. | [eCase Report](documentation-approach-12-07-cpg-derivative-and-related-assets.html#ecase-report) | See the applicable [Electronic Case Reporting IG](https://hl7.org/fhir/us/ecr/). Registry submissions and guideline feedback can have separate contracts. |
| <a id="concept-event"></a>**Event**<br/>Formerly: CPGEvent | A record of an activity underway, performed or explicitly recorded as not done. | [Events](documentation-approach-12-05-cpg-careplan.html#events-in-a-care-plan) | Use the applicable [event profile](profiles.html#activity-profiles) and its resource-specific status and request link. |
| <a id="concept-evidence"></a>**Evidence**<br/>Formerly: CPGEvidence | The findings that inform a recommendation, together with their sources and assessment of quality. | [Quality of Evidence and Evidence for Recommendations](documentation-approach-12-03-cpg-plan.html#quality-of-evidence-and-evidence-for-recommendations) | Guideline citations and recommendation metadata. [FHIR R4 Evidence](https://hl7.org/fhir/R4/evidence.html) and [EvidenceVariable](https://hl7.org/fhir/R4/evidencevariable.html) can express applicable evidence information. |
| <a id="concept-guideline"></a>**Guideline**<br/>Formerly: CPGGuideline | The package of computable content, dependencies, examples and documentation for the guideline. | [Guideline](documentation-approach-12-07-cpg-derivative-and-related-assets.html#guideline) | [CPGComputableGuideline](StructureDefinition-cpg-computableguideline.html) (ImplementationGuide) |
| <a id="concept-measure"></a>**Measure**<br/>Formerly: CPGMeasure | A defined quantitative assessment, often of a care process or outcome across a population. | [Measure](documentation-approach-12-07-cpg-derivative-and-related-assets.html#measure-ecqms) | FHIR R4 Measure and MeasureReport. See the [Quality Measure IG](https://hl7.org/fhir/us/cqfmeasures/). |
| <a id="concept-metric"></a>**Metric**<br/>Formerly: CPGMetric | A patient-level indicator such as elapsed time from proposal to documented action or progress toward a goal. | [Metrics](documentation-approach-12-07-cpg-derivative-and-related-assets.html#metrics) | Definition: [CPGComputableMetric](StructureDefinition-cpg-computablemetric.html) (Measure). Result: [CPGMetricReport](StructureDefinition-cpg-metricreport.html) (MeasureReport). An inferred case feature can also represent a result where appropriate. |
| <a id="concept-pathway"></a>**Pathway**<br/>Formerly: CPGPathway | A longitudinal grouping of strategy and workflow definitions for guideline-directed care. | [Pathways](documentation-approach-12-03-cpg-plan.html#pathways) | [CPGPathwayDefinition](StructureDefinition-cpg-pathwaydefinition.html) (PlanDefinition with type `clinical-protocol`) |
| <a id="concept-pathway-eligibility-criteria"></a>**Pathway Eligibility Criteria**<br/>Formerly: CPGPathwayEligibilityCriteria | The logic that determines whether a patient meets the clinical scope of a pathway. | [Pathway Eligibility](documentation-approach-12-03-cpg-plan.html#pathway-eligibility) | Applicable expressions. Reusable cohorts may use [CPGGroupDefinition](StructureDefinition-cpg-groupdefinition.html). |
| <a id="concept-pathway-enrollment-criteria"></a>**Pathway Enrollment Criteria**<br/>Formerly: CPGPathwayEnrollmentCriteria | Logic that determines when to propose or initiate enrollment. | [Pathway Enrollment Criteria](documentation-approach-12-03-cpg-plan.html#pathway-enrollment-criteria) | Applicable definition and enrollment patterns, including [CPGEnrollmentActivity](StructureDefinition-cpg-enrollmentactivity.html) for a proposed enrollment activity. |
| <a id="concept-pathway-enrollment-status"></a>**Pathway Enrollment Status**<br/>Formerly: CPGPathwayEnrollmentStatus | The current or historical state of a patient’s participation in a pathway. | [Pathway Enrollment](documentation-approach-12-03-cpg-plan.html#pathway-enrollment) | Status of [CPGCase](StructureDefinition-cpg-case.html) (EpisodeOfCare), with `enrolledIn` identifying the relevant definition. |
| <a id="concept-plan"></a>**Plan**<br/>Formerly: CPGPlan | Reusable guidance for a class of patients, expressed through recommendation, strategy and pathway definitions. | [Plan](documentation-approach-12-03-cpg-plan.html) and [Plan, Planning, and Care Plan](documentation-approach-12-02-separating-and-defining-case-plan-and-workflow.html#plan-planning-and-care-plan) | [CPGRecommendationDefinition](StructureDefinition-cpg-recommendationdefinition.html), [CPGStrategyDefinition](StructureDefinition-cpg-strategydefinition.html), [CPGPathwayDefinition](StructureDefinition-cpg-pathwaydefinition.html) |
| <a id="concept-proposal"></a>**Proposal**<br/>Formerly: CPGProposal | A patient-specific suggestion to perform or avoid an activity. | [Proposal](documentation-approach-12-05-cpg-careplan.html#proposal) | Use the applicable request profile with intent `proposal`. When a RequestGroup carries the proposal intent, its child requests use `option`. |
| <a id="concept-recommendation"></a>**Recommendation**<br/>Formerly: CPGRecommendation | A guideline recommendation, with its applicability criteria and recommended activity, expressed as an ECA rule | [Recommendations](documentation-approach-12-03-cpg-plan.html#recommendations) | [CPGRecommendationDefinition](StructureDefinition-cpg-recommendationdefinition.html) (PlanDefinition) |
| <a id="concept-request"></a>**Request**<br/>Formerly: CPGRequest | A patient-specific representation of desired care. Its intent distinguishes a proposal, plan or order where supported. | [Requests](documentation-approach-12-05-cpg-careplan.html#requests-in-a-care-plan) | Use the applicable [request profile](profiles.html#activity-profiles). The request’s intent is separate from its status and any associated Task or Event. |
| <a id="concept-strategy"></a>**Strategy**<br/>Formerly: CPGStrategy | A grouping of related recommendations for a clinical concern or context. | [Strategies](documentation-approach-12-03-cpg-plan.html#strategies) | Definition: [CPGStrategyDefinition](StructureDefinition-cpg-strategydefinition.html) (PlanDefinition with type `workflow-definition`). Patient-specific options: [CPGStrategy](StructureDefinition-cpg-strategy.html) (RequestGroup). |
| <a id="concept-workflow"></a>**Workflow** | The actors, timing, dependencies and interactions through which care is delivered | [Workflow and Common Pathway](documentation-approach-12-06-cpg-common-pathway.html) | The Common Care Pathway provides an abstract process model. Local work can use the FHIR Request, Task and Event patterns. |
